# 《问心劫》核心体验设计基准

状态：2026-09-28 的目标与改稿基准，不是已实现功能清单。详细剧本工作稿见 `INTEGRATED_STORY_DRAFT.md`，工程实况见 `DEVELOPMENT_STATUS.md`。此前 114 个节点、约 8,255 个剧情字符且没有完整结局的版本不能满足六小时目标；现已接上短篇可玩结局，但新增内容也须经玩家验证，不能仅凭节点数宣称达标。

## 定位与验收

《问心劫》是互动式修仙悬疑小说。玩家首先要愿意读下去、关心书中的人；证据比较、术法验证和有代价的选择为故事增加参与感与新鲜体验，不按解谜题或刷时长来倒排剧情。修仙是人物感知线索、改写命运的本领，也应是世界、气韵和人物欲望的一部分。

最高优先级是好玩：每段调查都应带来理解的变化、可执行的新办法，或有分量的人物冲突。玩家可通过多周目累计获得至少六小时有趣的新鲜体验，不要求首次通关独占六小时；不同周目须有实质不同的调查、人物互动和行动后果，共通剧情重读、等待、刷属性及失败重试不计入。由未参与制作的玩家验证时间与体验。

三十日日程、六幕、每日两行动、随机事件牌与重复修炼采集不再是既定方案。剧情需要真实可信的期限，但具体经过多少天应由案件和人物行动决定，不为凑行动次数固定。现有十日内容可作为改写素材，不要求原样续接，也不要求立即删去已运行的切片。

## 主角与调查动机

拟定主角是刚入宗、已有炼气基础的外门司籍弟子，负责誊录入门名册与部分物资去向。登仙帖背面被刮去的旧名，与失踪弟子记录、炉房账目出现矛盾；主角起初只想弄清自己的入宗资格，随后发现同批弟子和自身都可能受牵连。主角不是奉命破案的执法者，司籍身份只提供有限接触机会；禁地、证人和原始阵图仍需凭术法、关系或承担风险才能接近。

朱印共鸣可以保留为旧阵曾触及主角的痕迹：它带来危险与调查入口，但不是独一无二的救世血脉，也不能代替学习、求证和抉择。主角入宗前已有基础，故事中的成长重点是掌握并运用辨气、灵识、符箓和阵理等具体本领，而非短时间跨越多个大境界。术法来源、教学和使用条件都须在剧情中交代。

## 核心谜案循环

1. 发现可核对的异常：名册、炉账、证词、法器或阵法残痕各揭示一部分事实，来源与可靠性清楚可辨。
2. 比较并提出判断：玩家能在关键时刻选择追查哪种解释，或拿具体证据质问某人；游戏不替玩家直接宣布唯一正确答案。
3. 用合适的修仙手段验证：灵识可辨残留气息，阵理可复现局部机制，符箓可进入危险地点。凡人证词与术法证据可能互相冲突，但术法也有范围和误判风险。
4. 让判断改变行动：猜错、过早公开或相信错人会引起人物回应和机会成本，不以一次答错直接锁死主线；查清真相后还要处理救人、稳阵和公开旧罪的冲突。

不增加仅为陈列而存在的线索板、合成小游戏或结尾考试。若制作推断/对质交互，证据必须对人物、可用方法或后续事件产生实际影响；信息不足时仍应有代价明确的替代调查入口。

## 修仙爽点与边界

- 成长要可见：早期看不见的阵气，习得灵识后可辨；曾无法接近的炉房，学会符术或取得协助后可进入；终局能亲自参与改阵或抵御阵压。每项能力至少在后续谜案与行动中发挥作用，不只显示数值增加。
- 力量要带来主动权：宗门可以觊觎主角的修为，但不能把认真修炼设计成惩罚玩家的陷阱。风险来自使用力量的方式、准备是否充分和愿意承担的责任。
- 境界推进要可信：优先呈现炼气阶段的技艺精进和关键突破，不为六小时时长强行安排多次飞升。修炼片段服务于调查、人物关系和终局准备，不做无限刷点。
- 高潮要兑现所学：玩家以自己掌握的术法、获得的证据和争取到的人手执行决定，而不是听完长老解释后只选一个结局按钮。

第一段体验可用一条闭环验证：旧名、炉账和当事人说法互相矛盾；玩家学习并使用一种术法验证其中一处，形成可用于对质的新判断；对质改变人物关系或接下来的行动。具体线索与术法效果仍须在剧本设计时推敲，不能把这个示例当成已完成内容。

## 人物、主题与结局

林月、沈砚、顾衡各自掌握部分真相，也有可信的隐瞒理由和想保护的人。关系不是可重复刷满的好感度；合作需要理解其立场、履行承诺，并面对互相冲突的目标。谜案应逐步从“谁失踪了”推进到“旧阵为何如此运作”“停炉会伤害谁”“有没有经过验证的替代办法”。

“问心”不是道心数值或结尾善恶问答，而是当玩家有能力改变局面后，必须决定让谁承担代价、自己承担多少。“劫”既指旧阵与裂隙造成的灾劫，也指主角在力量和责任之间的心劫。主题须贯穿调查与行动，不能只在标题和结局独白中出现。

旧阵需要在一个有故事依据的期限前续阵；“登仙大典”表面是选拔，实际可能以弟子补充阵力。不续阵会使裂隙危及村民，照常续阵则延续牺牲。期限、仪式机制与各方知情程度尚需剧本验证，不预设恰好第三十日，也不同时写“固定日期”和“大典提前”的矛盾说法。

目前保留四种结局方向作为待验证方案，而不是四个按总分发放的结局文案：替阵救众、携人离山、夺炉自立、维持旧阵。替阵是准备充分、代价仍真实的较理想方向；离山救得了部分人却留下山中的债；维持旧阵暂保村民但继续献祭；夺炉的结果取决于如何使用力量及让谁承压。重要代价必须在选择前有合理预期，不设二周目才可解锁的唯一正确答案。结局数量和条件以完整剧本及试玩为准。

## 制作顺序（全程版本）

1. 先完成从开篇到所有尾声的完整故事剧情，再扩为逐场可读的小说式正文，审读人物、悬念、口吻与因果。当前 JSON 和旧十日素材都只是原型，不以已实现功能决定故事。
2. 从写好的场景里确定互动抉择与术法演出，才在正式入口和 Demo 制作连续可玩的版本。每个选择应改变人物行动或后果；不为节点数和时长临时增设调查环节。
3. 完整版本成形后由未参与制作的人无提示游玩多个周目，验证阅读兴趣与新增体验累计至少六小时；根据反馈改写薄弱篇章，再做必要的 Unity、存读档和 Windows 构建检查。

规则层负责证据、能力、条件、后果与存档；剧情数据负责事实、对话和分支；展示层负责让玩家看清线索、人物反应与术法演出。保持 Rider C# 格式、可读职责边界、TMP 文字及现有水墨美术方向。新增图片、音频和字体必须原创或有明确商业使用许可。
