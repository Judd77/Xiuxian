# 下一步：先完成小说，再编排互动

目标见 `GAME_REDESIGN.md`；从开篇到四个终局的完整因果与人物弧线见 `INTEGRATED_STORY_DRAFT.md`；工程现状见 `DEVELOPMENT_STATUS.md`。玩家希望读到的是互动式修仙小说，术法与选择服务故事，不靠临时添加调查节点凑时长。当前游戏数据仍是短篇原型，不等于故事定稿。

1. **先写逐场正文。**依全程剧情稿，连续写完共同开局、林月篇、顾衡篇、沈砚篇、汇合高潮和四种尾声。每场写出场景中的人、行动、对白、情绪转折和悬念，不把设计结论直接写给读者。写完一整段再回头审读文笔、节奏和人物口吻。
2. **做全稿因果审读。**核对旧帖、旧号、许澄身份、初试停铃、旧灾两处符裂、祁元肃改高上限、灵潮期限和新阵代价在所有路线中是否一致。每条人物线应有独占但非必需的发现；单周目能读懂结局，其他周目能读到新的人物与后果。没有完整正文的段落不直接新增 `Campaign.json` 节点。
3. **再决定互动位置。**只在人物真正面临抉择、术法有可见效果或读者能凭已有信息判断时安排选择。按已经写好的场景倒推需要的证据、条件、存档状态、UI 与美术。先在纸上读通全部分支，再改游戏数据；Demo 在第一卷末收束，须有小说式悬念。
4. **然后制作与验证。**按定下的剧本逐卷重写 Unity 正式版和独立 Demo，保留可用系统，替换说明书式旁白。每完成一项可玩的剧情任务单独 Git 提交；必要的 Unity 剧情图、存读档及画面检查跟随该任务进行。
5. **最后验证时长与发行。**请未参与制作的人无提示游玩多个周目，记录新增体验时长和阅读感受；共通重读不计入至少六小时的新鲜体验。达到故事与试玩质量后再核查 Steam 双 App、构建、云存档和商用资产。当前 Demo 不作为可发布内容。
