# 第一卷《雨叩山门》剧情结构

更新：2026-09-24。本文记录正式入口 `Campaign.json` 的当前纵向切片结构，不包含旧 Prototype 兼容要求。

## 当前规模

- 剧情版本：revision 2；开发期旧存档直接失效，不制作迁移层。
- 图节点：41 个，结构可达性校验覆盖全部节点。
- 单路线：约 22 个阅读节点，约 1600–1700 个正文字符。
- 当前只能视为章节骨架；15–20 分钟目标仍须补内容并通过人工计时试玩确认。

## 流程

1. 山门入宗，发现登仙帖背面被刮去的旧名。
2. 林月给出名册与松风岭两个时间敏感线索。
3. 玩家只有两个时辰，可在调查、赴约、修炼之间取舍。
4. 每次行动内部再选择执行方式，决定证据质量、关系、修为或风险。
5. 入夜后根据名册线索与林月信任进入四种结果之一。
6. 第二日根据结盟、名册或共鸣状态开放不同调查入口。

## 路线矩阵

| 白日状态 | 夜间结果 | 第二日优势 |
| --- | --- | --- |
| 名册 + 林月信任 | `c01.shared` | 结盟潜查药炉 |
| 仅名册 | `c01.alone` | 沿名册追查失踪弟子 |
| 仅林月信任 | `c01.guarded` | 获得同伴与轮值表方向 |
| 无名册且未赴约 | `c01.uneasy` | 可通过山腹共鸣寻找炉心 |

## 当前状态变量

`day`、`actions`、`cultivation`、`trust.linYue`、`clue.register`、`clue.jade`、`mark.resonance`、`risk.attention`、`visited.linYue`、`route.alliance`。

新增变量必须支撑可见选择后果。开发期不为删除或改名的变量提供旧档兼容；公开发行后再建立明确的存档迁移政策。

## 场景绑定

- `gate`：山门与白日行动枢纽。
- `ridge`：松风岭会面与修炼。
- `night`：第一夜通用外景与暗道。
- `stele`：旧碑廊和名册路线。
- `quartersNight`：弟子居所夜间搜查。
- `mountainHeart`：山腹石门与共鸣路线。

## 下一轮内容

1. 通过人工试玩记录真实阅读时长与选择停留时间。
2. 在不增加新系统的前提下，为每条白日行动补一段人物或环境反馈，使单路线达到目标时长。
3. 为线索首次收录增加轻量反馈，避免玩家只能从顶栏数字变化察觉新证据。
4. 制作林月表情差分，再引入第二名有完整立绘的主要角色。
